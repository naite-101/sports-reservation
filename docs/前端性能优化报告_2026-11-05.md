# 体育馆小程序前端性能 & 体验优化报告

> 优化范围：`miniprogram` 前端源码。所有改动均为**纯体验/性能优化**，不改变任何业务逻辑与权限判断；后端鉴权（info_completed、黑名单、二维码 token、签到）一律保持不变并继续作为唯一安全依据。

---

## 一、问题根因汇总

### 1. 个人信息填写页面闪现

- **根因**：`app.js` 冷启动后**没有任何本地缓存**，用户信息全靠页面 `onShow` 异步调 `passport/login` 才拿到。首页 `data.role` 初始为 `0`，`index.wxml` 里 `wx:if="{{role === 0}}"` 会先渲染出「完善信息」提示卡片，等接口返回 `role=1` 才消失 → 闪烁。
- 同时 `profile.js` 的 `onLoad` 直接异步 `loadProfile()`，页面**先渲染空表单**，`my/profile` 返回后才填充 → 已完善用户会先看到「可编辑表单」再变成「锁定态」。

### 2. 「我的」页面抖动闪烁

- **根因**：`mine.js` 的 `data.user` 初始为 `null`，`mine.wxml` 直接渲染 `{{user.name || '未完善信息'}}`、三个统计数字等，接口未返回时 `user` 为 null，头像框/名字/统计**全部塌陷**，返回后才填充 → 抖动、空白。
- `onShow` 每次都 `init()`，串行调 `passport/login` + `my/stats`，且 8 个页面各自重复调 `login`，没有去重缓存。

### 3. 签到二维码页面打开卡顿

- **根因**：`qrcode.js` 的 `refresh()` 是**串行两个请求**（先 `qrcode/valid_booking`，再 `qrcode/generate`），两个接口都返回后才 `drawQrCode` 绘制 canvas；期间 canvas 区域是空白的，无 loading 提示 → 打开后长时间空白卡顿。
- `onShow` 每次 `start()` 都会重新请求并重绘，且 `getBestMaskPattern`（8 遍 `makeImpl` + `getLostPoint`）是同步 CPU 计算，短暂阻塞主线程。

### 4. 通用性能问题

- **重复 login**：`index` / `booking` / `mine` / `admin` / `hr` / `blacklist` / `banner` / `stress` 共 8 处各自在 `onShow` 调 `passport/login`，来回切换 tab 反复请求。
- **首页串行 6 个请求**：`login` + `venue/list` + `my/reservations` + `banner/list` + `notice/list` + `notice/latest` 全串行 await，慢。
- **setData 未拆分**：`mine.init`、`index.init` 一次性写大对象，触发整页重渲染。

## 二、完整修改代码片段

### 1. 新增 `miniprogram/utils/cache.js`（缓存工具）

```js
/**
 * 轻量缓存工具：storage 持久化 + 内存 Map 双层缓存
 * ⚠️ 仅用于体验优化（防闪现/抖动），绝不作为业务权限判断依据。
 */
const PREFIX = 'gym_';
const mem = {}; // 内存缓存（会话内，避免反复同步读 storage）

function get(key, def) {           // 读：内存优先 → storage → 默认值
  const k = PREFIX + key;
  if (mem[k] !== undefined) return mem[k];
  try {
    const v = wx.getStorageSync(k);
    if (v === '' || v === undefined || v === null) return def;
    mem[k] = v; return v;
  } catch (e) { return def; }
}
function set(key, val) {           // 写：同时写内存与 storage
  const k = PREFIX + key; mem[k] = val;
  try { wx.setStorageSync(k, val); } catch (e) {}
}
function remove(key) {             // 删
  const k = PREFIX + key; delete mem[k];
  try { wx.removeStorageSync(k); } catch (e) {}
}
module.exports = { get, set, remove };
```

### 2. `miniprogram/app.js`（登录 + storage 缓存）

```js
const request = require('./utils/request.js');
const cache = require('./utils/cache.js');
const USER_CACHE_KEY = 'user_cache';
const USER_CACHE_TTL = 5 * 60 * 1000; // 5 分钟内复用，减少重复 login

App({
  onLaunch() {
    if (!wx.cloud) { /* 版本过低提示 */ return; }
    wx.cloud.init({ env: config.CLOUD_ID, traceUser: true });
    // 冷启动异步拉取用户信息，同步写入 storage+内存，供页面 onLoad 同步读取，消除闪现
    this.refreshUserInfo();
  },
  globalData: {
    userInfo: null, role: 0, noticePopped: false, bannerCache: null, _userCacheAt: 0,
  },

  /** 同步读用户缓存（内存 > storage），无则 null */
  getUserCache() {
    if (this.globalData.userInfo) return this.globalData.userInfo;
    const c = cache.get(USER_CACHE_KEY, null);
    if (c) { this.globalData.userInfo = c; this.globalData.role = Number(c.role) || 0; }
    return c;
  },
  /** 写用户缓存（storage + 内存） */
  setUserCache(user) {
    if (!user) return;
    this.globalData.userInfo = user;
    this.globalData.role = Number(user.role) || 0;
    this.globalData._userCacheAt = Date.now();
    cache.set(USER_CACHE_KEY, user);
  },
  /** 刷新用户信息（后端为准），TTL 内复用缓存不发请求 */
  async refreshUserInfo(force) {
    const now = Date.now();
    if (!force && this.globalData.userInfo && (now - this.globalData._userCacheAt) < USER_CACHE_TTL) {
      return this.globalData.userInfo;
    }
    try {
      const login = await request.call('passport/login', {}, { silent: true });
      this.setUserCache(login);
    } catch (e) { /* 网络失败保留旧缓存 */ }
    return this.globalData.userInfo;
  },
});
```

### 3. `miniprogram/pages/profile/profile.js`（防闪现，仅列 onLoad + loadProfile 改动）

```js
onLoad() {
  const app = getApp();
  const cached = app.getUserCache();
  // 缓存预判：已完善且无编辑权限(学生/普管) → 先不渲染表单，后端确认后直接跳走
  if (cached && cached.info_completed && Number(cached.role || 0) < 3) {
    this.loadProfile().then(() => {
      if (this.data.infoCompleted && this.data.role < 3) this.goBack(); // 后端确认后跳走
    });
    return;
  }
  this.loadProfile(); // 无缓存/未完善/有编辑权限 → 正常渲染
},
goBack() {
  const pages = getCurrentPages();
  if (pages.length > 1) wx.navigateBack();
  else wx.switchTab({ url: '/pages/index/index' });
},
async loadProfile() {
  try {
    const p = await request.call('my/profile', {}, { silent: true });
    const infoCompleted = !!p.info_completed;
    const role = Number(p.role) || 0;
    const locked = infoCompleted && role < 3;
    // 后端为准：同步更新本地缓存，避免旧缓存与后端不一致
    const app = getApp();
    const cached = app.getUserCache() || {};
    app.setUserCache(Object.assign({}, cached, { role, name: p.name || '', info_completed }));
    this.setData({ name: p.name||'', student_no: p.student_no||'', phone: p.phone||'',
      college: p.college||'', role, infoCompleted, locked, ready: true });
    return { infoCompleted, role };
  } catch (e) { this.setData({ ready: true }); return { infoCompleted: false, role: 0 }; }
},
```

`save()` 成功后追加：`app.setUserCache(Object.assign({}, cached, { info_completed: true, name }));`（保存即同步缓存，下次进入不再闪现）。

`profile.wxml`：外层用 `wx:if="{{!ready}}"` 显示骨架屏，`wx:else` 渲染表单（`ready` 确认后才渲染）。

### 4. `miniprogram/pages/mine/mine.js`（骨架屏 + 缓存）

```js
data: { user: null, role: 0, roleName: '', blackDays: 0,
        stats: { total_count: 0, month_count: 0, no_show_count: 0 }, loaded: false },

async init() {
  const app = getApp();
  // 1. 缓存优先渲染：有用户缓存先同步填充，消除 user=null 布局塌陷
  const cached = app.getUserCache();
  if (cached) this.setData({ role: Number(cached.role)||0, roleName: cached.role_name||'',
      blackDays: cached.black_days||0, user: cached, loaded: true });

  // 2. 后端为准：异步刷新 login（TTL 去重，切 tab 不再重复请求）
  try { const login = await app.refreshUserInfo();
    if (login) this.setData({ role: Number(login.role)||0, roleName: login.role_name||'',
        blackDays: login.black_days||0, user: login });
  } catch (e) {}

  // 3. 预约统计（独立 setData，与上面拆分避免整页重渲染）
  if (this.data.role >= 1) {
    try { const stats = await request.call('my/stats', {}, { silent: true });
      this.setData({ stats: stats || { total_count:0, month_count:0, no_show_count:0 } });
    } catch (e) {}
  }
  this.setData({ loaded: true });
},
```

`mine.wxml`：`profile-card` 与 `stats-card` 用 `wx:if="{{!loaded}}"` 显示骨架屏（`.skeleton-circle` + `.skeleton-line`），`wx:else` 渲染真实内容；静态菜单列表始终渲染。

### 5. `miniprogram/pages/qrcode/qrcode.js`（loading + 并行请求）

```js
data: { booking: null, hasValid: false, countdown: 20, size: 220, loading: true },

onShow() { if (this.timer) return; this.start(); }, // 定时器仍在运行不重复 start
start() { this.refresh(); this.timer = setInterval(() => this.tick(), 1000); },
tick() { let c = this.data.countdown - 1;
  if (c <= 0) this.refresh(); else this.setData({ countdown: c }); }, // 20 秒刷新保留

async refresh() {
  this.setData({ loading: true });
  try {
    // 并行请求，消除串行等待（打开更快）
    const [valid, gen] = await Promise.all([
      request.call('qrcode/valid_booking', {}, { silent: true }),
      request.call('qrcode/generate', {}, { silent: true }),
    ]);
    this.setData({ booking: valid && valid.has_valid ? valid.booking : null,
      hasValid: !!(valid && valid.has_valid), countdown: 20 });
    qrUtil.drawQrCode('qrcode', gen.token, this.data.size, this);
    this.setData({ loading: false });
  } catch (e) { this.setData({ countdown: 20, loading: false }); }
},
```

`qrcode.wxml`：canvas 始终渲染，`wx:if="{{loading}}"` 用 `.qr-loading-mask` 覆盖其上显示 loading；`qrcode.wxss` 新增 `.qr-loading-mask`、`.qr-loading-spinner` 样式。

async init() {

## 三、关键安全注意事项（重点强调）

1. **storage 缓存只做体验优化，绝不做安全判断**：本次引入的 `user_cache`、`_venueCache`、`_noticeCache` 仅用于消除闪现/抖动、减少重复请求，**不可作为任何权限依据**。用户可随时清除或篡改 `wx.storage`。
2. **后端仍独立校验所有权限**（未做任何削弱）：
   - 预约 `reservation/create`：后端校验 `info_completed`（4010）、黑名单（4004）、场地占用（4100）、学生时段锁（4101）、验证码（4200~4202）、限流（4203）。
   - 二维码 `qrcode/generate`、`qrcode/valid_booking`：后端校验黑名单与有效预约；`qrcode/scan` 用**服务端时间**校验 20 秒 token 有效期，不依赖前端计时，截图旧码必然失败。
   - `application.js` 鉴权中间件对 `isBlockedRoute`（预约/二维码）做黑名单拦截，**与前端 storage 无关**。
3. **缓存与后端不一致时，一律以后端为准**：`profile.loadProfile`、`mine.init`、`index.init` 都是「缓存先渲染 → 后端结果覆盖并回写缓存」，确保后端状态（如管理员重置信息、手动拉黑）能及时反映，不会被旧缓存绕过。
4. **清除缓存场景安全**：`getUserCache()` 无缓存返回 `null`，页面走完整 `passport/login` 流程，不会因缺少 storage 而逻辑错乱或误判权限。

## 四、通用全局优化建议

1. **接口缓存**：`passport/login` 已在 app 层做 5 分钟 TTL 缓存；`venue/list`、`notice/list` 在首页做 60 秒会话缓存。其它低频且变化快的接口（`my/reservations`、`reservation/status`）不缓存，保证实时性。
2. **分包**：项目当前为单包，页面约 20 个。可将 `admin/*`（7 个管理页）、`stress`、`developer`、`feedback` 等低频页面拆到分包，降低主包体积与首屏加载时间。
3. **图片优化**：轮播图用 `getTempFileURL` 临时链接并缓存；建议 banner 上传前压缩（≤ 500KB/张），`localBanners` 兜底图确认尺寸合理，避免 aspectFill 大图内存峰值。
4. **setData 规范**：只传本次变化的字段（本次已拆分 mine 的 login/stats、index 的 login/venues/notice）；避免把整个大列表反复整体重写；列表项更新用 `setData({'array[index].field': value})` 路径式更新。
5. **页面生命周期**：`onShow` 里区分「首次进入」与「返回刷新」，用页面实例字段（`this._xxx`）或 `app.globalData` 做会话内缓存，避免每次 onShow 全量重拉。
6. **同步耗时计算**：二维码 `getBestMaskPattern` 为同步 CPU 计算，token 较短（版本 1~2、moduleCount 21~25），耗时可控；若日后 token 变长可考虑降 ECC（M→L）或缩小绘制尺寸，不必引入 Worker。
7. **跳转方式**：已核对——tabBar 页面间用系统切换、`navigateTo` 用于二级页、`reLaunch` 仅 `stress` 压测页复位用，均合理，无需改动。
