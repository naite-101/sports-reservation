# 体育馆预约微信小程序 — 产品需求文档（PRD）

## 1. 项目信息

| 项 | 内容 |
|---|---|
| 语言 | 中文 |
| 项目名称 | gymreserve |
| 技术栈 | 微信小程序 + 微信云开发（云函数 + 云数据库 + 云存储 + 定时触发器） |
| 鉴权方式 | 微信 openid |
| 文档版本 | v1.0 |

**原始需求复述**：为校内学生提供线上预约体育馆运动场地的微信小程序，简化签到、场地管理、公告通知工作。全场馆预约免费，无线上支付。

---

## 2. 产品定义

### 2.1 产品目标

1. 让学生可在线查看三馆场地状态并完成「先到先得」的免费场地预约，取代线下排队。
2. 通过动态二维码 + 服务端校验实现「防截图」签到，并由系统自动判定爽约/自动拉黑，规范场馆使用秩序。
3. 让管理员通过扫码签到、黑名单管理、公告发布、场地闭馆等能力，高效完成日常运营。
4. 通过「老师/现任主席」人事权限，实现管理员任免、权限分配与成员信息维护，形成完整权限闭环。
5. 支撑 21:00 高峰期不低于 200 人同时抢约且不超约，保证核心预约链路稳定可靠。

### 2.2 用户故事

- 作为**学生**，我希望用微信授权登录并完善个人信息，以便获得预约资格。
- 作为**学生**，我希望查看羽毛球场/乒乓球场/健身房的场地状态（可预约/已约满/临时闭馆），以便选到合适的空闲场地。
- 作为**学生**，我希望在开放时间后选择场馆+场次+空闲场地提交预约，以便先到先得地锁定场地。
- 作为**学生**，我希望在场次开始前 30 分钟自主取消预约，以便释放场地并避免不必要的爽约。
- 作为**学生**，我希望在我的预约中查看全部记录及订单状态（待签到/已签到/已取消/已过期），以便掌握自己的预约情况。
- 作为**学生**，我希望查看个人身份动态二维码（每 20 秒刷新），以便到场扫码签到；二维码需服务端校验防截图。
- 作为**学生**，我希望查看近 7 天预约记录与签到记录，以便回溯自己的使用历史。
- 作为**学生**，我希望进入小程序时自动弹出最新公告，以便及时获知场馆通知。
- 作为**学生**，我希望在被拉黑时收到「N 天内不可预约」的明确提示，以便了解受限原因。
- 作为**普通管理员**，我希望扫学生动态二维码完成签到，以便在签到时间窗口内确认到场并登记附属人员。
- 作为**普通管理员**，我希望手动拉黑违规学生并自定义时长、查看黑名单列表，以便执行违规管理（不可解除拉黑）。
- 作为**普通管理员**，我希望发布、修改、删除公告，以便向学生传递信息。
- 作为**普通管理员**，我希望按场馆、场次筛选查看当日签到数据，以便掌握到场情况。
- 作为**超级管理员**，我希望查看并手动解除黑名单，以便提前恢复学生预约资格；并保留拉黑/解除操作日志。
- 作为**超级管理员**，我希望按场馆设置具体场地临时闭馆/恢复开放，以便灵活管理场地。
- 作为**超级管理员**，我希望查看系统日志（拉黑记录、管理员操作记录），以便审计追溯。
- 作为**老师/现任主席**，我希望任免普通管理员、分配/调整/禁用权限、维护成员信息，以便完成人事管理，并兼任超级管理员全部权限。

## 3. 技术规范

### 3.1 需求池

#### P0（核心闭环，必须）

| 编号 | 功能 | 验收标准 |
|---|---|---|
| P0-1 | 微信登录鉴权 | 学生/管理员/超级管理员/老师/主席均通过微信 openid 登录；未登录仅可浏览公告 |
| P0-2 | 学生完善个人信息 | 未完善信息不可预约，仅可浏览公告；完善后可预约 |
| P0-3 | 场地预约 | 可查看三馆场地状态；仅在开放时间（前一天 21:00 后）可预约；选场馆+场次+空闲场地提交；同一场地同一场次仅一名学生可约；先到先得 |
| P0-4 | 预约取消 | 场次开始前 30 分钟可自主取消；超过时间不可取消 |
| P0-5 | 我的预约 | 展示全部记录；订单状态=待签到/已签到/已取消/已过期（未签到且场次结束）；账号状态=正常/黑名单 |
| P0-6 | 个人身份动态二维码 | 每 20 秒刷新；服务端校验防截图；展示当前有效预约信息，无有效预约给提示 |
| P0-7 | 记录查询 | 近 7 天预约记录（含已取消/已完成）；签到记录（到场签到时间+场地场次） |
| P0-8 | 公告查看 | 进入小程序自动弹出最新公告；小程序内有公告入口 |
| P0-9 | 黑名单提示 | 被拉黑进入小程序提示「您已被限制预约，N 天内不可预约场馆」，预约按钮置灰、二维码不可打开 |
| P0-10 | 扫码签到 | 扫动态二维码显示学生信息+场次+场馆；支持添加附属人员（数量不限，非系统用户）；签到成功标记已签到；签到窗口=场次开始前 15 分钟至场次结束；场次结束未签到视为爽约；失败提示（无对应预约/场次不匹配/二维码过期） |
| P0-11 | 学生拉黑（手动） | 可自定义拉黑时长；查看黑名单列表（学生、拉黑时间、到期时间）；普通管理员不可解除 |
| P0-12 | 公告发布 | 编辑标题+内容；发布后学生可见；支持删除、修改 |
| P0-13 | 签到记录查看 | 查看当日签到数据；可按场馆、场次筛选 |
| P0-14 | 黑名单解除 | 查看全部黑名单（显示拉黑原因）；可手动解除；保留拉黑/解除操作日志（谁拉黑、谁解除） |
| P0-15 | 场地闭馆 | 按场馆选具体场地编号设置临时闭馆/恢复开放；闭馆后学生不可预约 |
| P0-16 | 系统日志 | 查看拉黑记录、管理员操作记录 |
| P0-17 | 爽约自动拉黑 | 场次结束未签到 → 系统自动拉黑 10 天；到期自动解除 |
| P0-18 | 人事管理 | 老师/主席：任免普通管理员、分配/调整/禁用/删除权限；查看学生名单及个人信息、修改学生信息；兼任超级管理员全部权限 |

#### P1（重要）

| 编号 | 功能 | 验收标准 |
|---|---|---|
| P1-1 | 预约须知 | 底部三个入口「预约 / 预约须知 / 我的」 |
| P1-2 | 消息推送 | 预约成功提醒、预约即将开始提醒、公告推送（微信订阅消息） |
| P1-3 | 活动图片更换 | 超级管理员可更换小程序活动图片 |

#### P2（可选扩展）

| 编号 | 功能 | 验收标准 |
|---|---|---|
| P2-1 | 基础配置 | 场次时间、预约开放时间参数可配置（默认值：工作日 2 场、周末 6 场、前一天 21:00 开放） |

### 3.2 业务基础数据与约束规则

- **场馆**：羽毛球场 6 个场地、乒乓球场 6 个场地、健身房 20 个场地（场地按场馆内编号 1~N）。
- **场次**：
  - 周一至周五：18:20~19:30、19:40~20:50（2 场）。
  - 周六至周日：13:00~14:10、14:20~15:30、15:40~16:50、17:00~18:10、18:20~19:30、19:40~20:50（6 场）。
- **开放规则**：前一天晚上 21:00 开放次日全部场次预约（例：周一 21:00 开放周二）。
- **预约策略**：先到先得（以提交成功时间为准）；同一场地同一场次仅一名学生；同一学生同一时间段仅可预约 1 个场地。
- **拉黑规则（两条独立通道，务必区分）**：
  - 通道 A（系统自动）：爽约 = 场次结束仍未签到 → 系统自动拉黑，固定 10 天。
  - 通道 B（管理员手动）：普通管理员/超级管理员手动拉黑 → 拉黑时长由操作者自定义。
  - 共同规则：到期自动解除；超级管理员可手动提前解除；解除均记录操作日志。
- **闭馆规则**：按场次判定，不是按天封锁。取场地的闭馆恢复时刻，与所选场次的开始时间比较：场次开始时间 ≥ 恢复时刻 → 可预约；开始时间 < 恢复时刻 → 该场次不可预约；永久闭馆（恢复时刻为 0）→ 全部场次不可预约；恢复时刻已过 → 自动恢复开放。

### 3.3 非功能需求

| 项 | 要求 |
|---|---|
| 并发 | 21:00 支持 ≥200 学生同时抢约、不超约（云函数事务保证先到先得） |
| 响应 | 页面/接口响应 < 2 秒 |
| 二维码安全 | 20 秒刷新，服务端校验，截图二维码无法签到，不依赖前端时间 |
| 权限隔离 | 普通管理员不可解除黑名单、不可分配管理员权限；人事权限仅老师/主席 |

## 4. UI 设计稿描述（页面要素说明，无需画图）

### 学生端

- **预约首页**：顶部公告弹窗/入口；三馆入口（羽毛球/乒乓球/健身房）；每个场馆内展示场地编号与状态（可预约/已约满/临时闭馆）；日期+场次选择；空闲场地选择；提交预约按钮。黑名单时按钮置灰。
- **我的预约**：预约记录列表，每条含场馆、场次时间、场地编号、订单状态（待签到/已签到/已取消/已过期）；取消按钮（仅开始前 30 分钟可用）。
- **个人身份二维码**：动态二维码（20 秒刷新）；下方展示当前有效预约信息（场馆/场次/场地）；无有效预约时提示。
- **公告**：最新公告自动弹出；公告列表 + 详情（标题、内容、时间）。
- **预约须知**：底部 Tab「预约 / 预约须知 / 我的」；预约须知展示预约规则与开放时间说明。

### 管理端（普通管理员 / 超级管理员）

- **扫码签到**：扫码入口；扫码后展示学生信息 + 场次 + 场馆；「签到」按钮；附属人员登记（数量不限）；签到结果反馈（成功/失败原因）。
- **黑名单管理**：黑名单列表（学生、拉黑时间、到期时间、拉黑原因）；「拉黑」操作（自定义时长）；超级管理员多「解除拉黑」操作。
- **公告管理**：公告列表；新增/编辑（标题+内容）/删除。
- **签到记录**：当日签到数据列表；按场馆、场次筛选。
- **场地闭馆**：按场馆选择具体场地编号；设置临时闭馆/恢复开放。
- **系统日志**：拉黑记录、管理员操作记录（谁拉黑、谁解除）。
- **人事管理**（老师/主席）：管理员任免与权限分配、禁用/删除权限；学生名单与个人信息查看/修改。

## 5. 待确认问题清单

1. **同一时间段判定口径**：规则「同一学生同一时间段只能预约 1 个场地」中的「同一时间段」是否指「同一天同一场次」，还是允许跨场馆（如 18:20~19:30 的羽毛球场与乒乓球场）？需明确唯一约束字段。
2. **取消后的场地是否立即释放**：取消后该场地该场次是否立刻回到可预约状态供他人抢约？是否受「前一天 21:00」开放时间限制？
3. **爽约自动拉黑的触发时机**：由定时触发器在每场次结束后统一扫描标记，还是由签到云函数实时判定？需确认定时触发频率与容错（漏扫补偿）。
4. **附属人员登记的信息范围**：仅记录姓名，还是需记录联系方式等字段？是否需在签到记录中体现。
5. **公告弹窗策略**：最新公告每次进入都弹，还是仅未读时弹一次（需记录已读状态）？
6. **订阅消息触发来源**：预约成功/即将开始提醒是否依赖学生主动订阅授权；公告推送如何触达（订阅消息的模板与频次限制）。
7. **人事权限与超级管理员权限边界**：老师/主席「兼任超级管理员全部权限」，人事模块是否需独立操作日志（谁任免了谁、谁改了权限）？
8. **管理员身份识别**：普通管理员、超级管理员、老师、主席通过 openid 在数据表中配置角色，是否存在同一人兼具多角色的场景？优先级如何处理。
9. **黑名单解除后的历史记录**：解除后学生预约资格立即恢复，历史拉黑记录是否仍保留展示在「全部黑名单」中（用于审计）。
10. **场地编号复用**：三馆各自从 1 开始编号，系统中场地唯一标识是否采用「场馆 + 编号」组合键。
